# Internationalization and Accessibility

## Target
Persian and English first, then expandable locale packs. UI translations are not sufficient: agent system prompts, tool descriptions, error messages, onboarding and documentation must support locale-aware responses.

## Requirements
- Use translation keys, not embedded UI strings.
- Locale fallback: user locale -> English -> key.
- RTL support for Persian, Arabic and Hebrew. Direction must be set per locale.
- Do not mirror icons that represent universal actions; mirror layout components where needed.
- Dates, numbers, currencies and plural rules use locale-aware formatting.
- Font fallback for CJK, Cyrillic, Arabic and Latin.
- Agent responses follow the selected language unless the task requests otherwise.
- Connector operation names and API schemas remain stable; display labels are translated.
- Tests cover Persian RTL, English LTR, fallback, long text, keyboard navigation and screen-reader labels.

## Initial locales
fa-IR (RTL), en (LTR). Next packs: ar, tr, de, fr, es, ru, zh-CN, zh-TW, ja, ko, pt-BR, hi.

## Technical direction
Adopt a small, maintainable translation library compatible with Electron and static UI. Keep locale dictionaries in JSON. Avoid runtime dependence on remote translation services.
